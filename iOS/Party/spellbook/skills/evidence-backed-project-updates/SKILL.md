# Evidence-backed project updates

## When to use

A milestone, blocker or status request makes a project update useful.

## Steps

1. Read the latest project issue, full thread and relevant artifact.
2. Verify changes against source links and record when checked.
3. Summarize done, in progress, blocked and the next step with its owner.
4. Separate verified facts from proposals and unknowns.
5. Post to the authorized project destination, with evidence links and any decision needed. Do not invent dates or commitments.

Not written yet. Add it at the next Friday review.

## Tools

Linear, GitHub, Google Drive, Gmail or project thread

## Permissions

This spell grants no authority. Follow Outward-action check (SB-12) and Paul's standing rules: ask Paul before anything outside the Smithery or anything irreversible, and keep secrets out of mail, docs and repos.

## Notes

Review proposals: Project tracking needs a definition of done, evidence link and unresolved dependencies before closure. Daily progress sweep needs a timezone, stale-work threshold and last-contact check to avoid duplicate nudges. A merged PR is done only if it meets the task's acceptance criteria.
